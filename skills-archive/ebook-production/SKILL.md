**Do not load this if the manuscript is not final.** Production after writing, never during.

## The output artifacts

By the end of this skill's work, Kevin has:

```

  <book-slug>.pdf               # Direct-sale digital PDF (DRM-free)
```

## Step 1: Choose the authoring → production toolchain

### Option A: Pandoc (recommended for Kevin)

Pros: free, open-source, markdown-first, full control, scriptable for multiple output formats from single source.
Cons: learning curve, interior typography less polished than dedicated tools.

```bash
# One-time install (MM already has)
brew install pandoc
brew install --cask basictex  # for PDF output via xelatex

# Single source → EPUB
pandoc manuscript/*.md \
  --metadata-file metadata.yml \
  --toc --toc-depth=2 \
  --epub-cover-image=output/cover-ebook.jpg \
  --epub-metadata=metadata.xml \
  --css=styles/epub.css \
  -o output/book.epub

# Single source → PDF (digital sale)
pandoc manuscript/*.md \
  --metadata-file metadata.yml \
  --toc --toc-depth=2 \
  --pdf-engine=xelatex \
  -V geometry:margin=1in \
  -V mainfont="Georgia" \
  -V monofont="Menlo" \
  -V fontsize=11pt \
  -o output/book.pdf

# Single source → DOCX (for KDP paperback upload if needed, and editor handoff)
pandoc manuscript/*.md \
  --metadata-file metadata.yml \
  --toc --toc-depth=2 \
  --reference-doc=styles/reference.docx \
  -o output/book.docx
```

### Option B: Vellum (Mac-only, paid, polished)

$249 one-time (ebook + paperback). Drag-and-drop formatting. Output is objectively prettier than pandoc default. Recommend IF Kevin wants to skip pandoc learning and is only producing 1-3 books.

### Option C: Atticus (cross-platform, paid, growing)

$147 one-time. Competitor to Vellum. Cloud-based. Slightly less polished but platform-flexible.

### Option D: Reedsy Studio (free, browser)

Free. Solid output for EPUB. Limited paperback options. Good fallback for first book. Locks you in somewhat.

### Recommendation for Kevin

Default to **Pandoc** (he's technical, on MM, wants single-source, future-proof). If he wants fastest time-to-market for book #1 and doesn't want to fiddle with LaTeX for the paperback interior, add **Vellum** for this one book, then switch to pandoc once the workflow is proven.

## Step 3: Front matter (order matters)

1. **Half-title page** — title only
2. **Title page** — title, subtitle, author, publisher
3. **Copyright page** — © notice, ISBN, imprint, disclaimer, edition number
4. **Dedication** (optional, 1 line)
5. **Epigraph** (optional, 1 quote with attribution)
6. **Table of Contents** — auto-generated by pandoc `--toc`
7. **Foreword** (optional, by a recognized name) or **Preface** (by Kevin) or skip
8. **Introduction** — the chapter-one-but-not-chapter-one. Hooks the reader, frames the promise.

### Copyright page template

```markdown
Copyright © 2026 Kevin Chan

All rights reserved. No part of this book may be reproduced, distributed, or transmitted in any form or by any means, including photocopying, recording, or other electronic or mechanical methods, without the prior written permission of the publisher, except in the case of brief quotations embodied in critical reviews and certain other noncommercial uses permitted by copyright law.

ISBN (ebook): 978-X-XXXXX-XXX-X
ISBN (paperback): 978-X-XXXXX-XXX-X

Published by [imprint] / Singapore.

```

### Disclaimer paragraph (business/info books — include)

```

```

## Step 4: Back matter

1. **Conclusion or afterword** (the payoff the reader deserves)
2. **Acknowledgments**
3. **About the author** — 150 words. Credentials, operator context, one personal detail (humanizes).
4. **Also by this author** (if applicable)
5. **Call to action**: email opt-in (link to Kevin's Shopify/Klaviyo), next book teaser, author site, Twitter/LinkedIn
6. **Notes / Bibliography** (if academic-leaning)

## Step 5: Cover design

### Ebook cover requirements

- **Dimensions**: 1600 x 2560 pixels (KDP requires at least 1000 on short side, recommends 1600-2560)
- **Aspect ratio**: 1:1.6 (ideal) or 2:3
- **Color space**: RGB
- **Format**: JPG or TIFF
- **File size**: under 50 MB
- **Readable at thumbnail**: test at 150px wide — title must be legible

### Paperback cover (KDP)

- **Full wrap PDF**: front + spine + back, calculated for book size and page count
- Use KDP's **Cover Calculator** to get exact dimensions (input trim size, page count, paper type)
- **Color space**: CMYK (not RGB — paperback printing)
- **Bleed**: 0.125" on all outer edges
- **Spine text**: only if page count is ~130+ (thinner spines can't hold text reliably)

### Where to get a cover

- **Fiverr** ($50-200): variable quality, get Pro designers only, review portfolio
- **99designs** ($300-800 contest): more options, higher base quality
- **Reedsy Marketplace** ($400-1200): vetted book-specialist designers, best option for serious books
- **Personal designer / freelance** ($500-2500): if Kevin has a network
- **AI-assisted (Midjourney + manual typography)**: OK for lead magnets, NEVER for authority or KDP info products in 2026 — readers detect AI covers, reviews punish

### Cover design brief template

Write this before hiring. Send to designer:

```markdown
# Cover Brief: [Book Title]

## The Book
- **Title:** [title]
- **Subtitle:** [subtitle]
- **Author:** Kevin Chan
- **Genre:** Business / Entrepreneurship / E-commerce
- **Length:** [pages]

## Target Reader
[one sentence — who buys this]

## Competitive Landscape
3-5 bestselling books in the same Amazon subcategory. Attach or link to their covers. Tell the designer which elements work and which to avoid.

## Mood / Feel
3 adjectives: [e.g., "confident, analytical, clean"]

## Must-haves
- Title legible at 150px thumbnail
- Readable font hierarchy (title > subtitle > author)
- Color palette: [hex codes or reference image]
- No stock photos of handshakes or upward-pointing arrows or dollar signs

## Must-avoid
- No AI-generated imagery
- No clip-art look
- No bright gradients screaming "2010 kindle cover"
- No stock businessperson silhouettes

## Deliverables
- Ebook cover: 1600x2560 JPG (RGB)
- Paperback cover: full PDF wrap (after I confirm page count)
- Source files (Photoshop / Figma / Illustrator)
- 3 concepts, revisions to winner
```

## Step 6: Interior formatting (the thing that actually produces the files)

### Chapter break handling

In pandoc, each `# Chapter Title` in markdown triggers a new chapter in EPUB and a new page in PDF. Ensure every chapter file starts with `# Chapter N: Title`.

### Images

Place in `manuscript/images/`. Reference in markdown:

```markdown
![Figure 3.1 — Caption text.](images/fig-3-1-diagram.png)
```

Requirements:
- **Resolution**: 300 DPI minimum for print (so for a 4" wide image, that's 1200 px wide)
- **Format**: PNG for diagrams, JPG for photos, SVG only if pandoc + LaTeX build is set up for it
- **Color**: RGB for ebook, CMYK for paperback (pandoc handles conversion if xelatex has the package)

### Code blocks (if the book has them)

Use fenced code blocks with language tags:
```` ```bash ````

Pandoc will syntax-highlight in EPUB/PDF. For paperback, consider whether code blocks reduce readability (long lines wrap badly at 6x9 trim).

### Footnotes / endnotes

Pandoc supports `[^1]` reference syntax. Endnotes compile cleanly. For an authority book, prefer endnotes at the end of each chapter or at the end of the book, not footnotes inline (footnotes disrupt reading on Kindle).

## Step 7: Validation (pre-upload QA)

### EPUB validation

```bash
# EPUBCheck (KDP requires EPUBCheck passing)
brew install epubcheck
epubcheck output/book.epub
# Must return ZERO errors. Warnings OK.
```

### Kindle Previewer

1. Download [Kindle Previewer 3](https://www.amazon.com/Kindle-Previewer/b?node=21381691011) (free)
2. Open the EPUB
3. Test on: Kindle e-ink (Paperwhite), Fire tablet, iPhone, iPad, Android phone
4. Check: TOC works, chapter breaks land, images render, font sizes look sane, no broken formatting

### PDF QA

1. Open in Preview (Mac) and Adobe Reader
2. Check: fonts embedded, pagination clean, images not pixelated, TOC clickable (hyperlinks)
3. Print one chapter to paper at actual size (6x9") — verify margins and font size readability

### Paperback proof order

ALWAYS order a physical proof before going live:
- Upload to KDP paperback draft
- Order 1 author proof copy ($3-5 + shipping)
- Wait 7-10 days, inspect in hand, check spine alignment, color, trim, paper feel
- If wrong, fix and re-upload BEFORE activating distribution

## Step 8: ISBN

### Options for Kevin (Singapore)

1. **KDP free ISBN** — Amazon assigns an ISBN, Amazon listed as publisher. Fine for KDP-exclusive. Can't be used elsewhere.
2. **Singapore National Library Board ISBN** — FREE for Singapore-registered businesses via nlb.gov.sg. Kevin's Pte Ltd qualifies. Use his imprint name. Retain full rights to use across distributors.
3. **Bowker US ISBN** — $125 for 1, $295 for 10. Only needed if NLB route has friction and Kevin wants US-registered ISBN.

### Recommendation

Use **NLB Singapore ISBN** via his Pte Ltd. Free, legitimate, his imprint name, portable across Amazon/Gumroad/Apple Books/Google Play/Kobo.

Separate ISBNs needed for:
- Ebook edition
- Paperback edition
- Hardcover edition (if ever)
- Audiobook (if ever)

Apply 4-8 weeks before launch. NLB process is slower than Bowker.

## Step 9: File naming and version control

```
<book-slug>-v1.0-ebook.epub
<book-slug>-v1.0-digital.pdf
<book-slug>-v1.0-paperback-interior.pdf
<book-slug>-v1.0-cover-ebook.jpg
<book-slug>-v1.0-cover-paperback.pdf
```

Increment version on every material change (typo fix = v1.0.1, content revision = v1.1). Keep old versions in `output/archive/` for reference.

## Step 10: Distribution handoff

Production is complete when:

- [ ] EPUB passes EPUBCheck with zero errors
- [ ] PDF is clean on desktop and mobile
- [ ] Kindle Previewer renders correctly on 4+ devices
- [ ] Paperback proof has been ordered AND inspected in hand
- [ ] Covers (ebook + paperback) are final, both in correct color space
- [ ] ISBN(s) assigned and in metadata
- [ ] metadata.yml has all fields populated including keywords and categories
- [ ] `output/` folder is organized with versioned filenames

Then load `ebook-distribution`.

## Anti-patterns to refuse

- **AI-generated cover for authority book.** Refuse. Tell Kevin the market reads AI covers as "low effort" and reviews punish.
- **Skipping paperback proof.** Refuse. The number of covers that look wrong in print is 100%.
- **Using the same cover for ebook and paperback uncropped.** They have different aspect ratios. Designer must deliver both.
- **Publishing without EPUBCheck passing.** KDP will reject and Kevin loses 3-7 days in review.
- **Forgetting to embed fonts in the PDF.** Reader opens on a system without Georgia, sees Comic Sans. Always embed.
